# E3a support task

The frozen `banking_policy_4.json` and `banking_policy_12.json` have one entry for each Banking77 intent, in dataset label order. The entry ID is the exact dataset label, including its original capitalization and punctuation. The gold entry for a ticket is its gold intent's entry; its department, priority and identity requirement provide gold outcomes. Do not place these entries in the agent system prompt.

## Reproducible generation

`generate_policy(granularity)` publishes the rule used to make the committed JSON, and `load_policy(granularity)` reads the frozen artifact rather than regenerating it during a run. The seed is the literal UTF-8 string `e3a-policy-v1`. For each intent compute SHA-256 of `seed:partition:intent`, sort by digest then intent, and assign rank modulo 4 or 12 to `department_00`, etc. SHA-256 of `seed:rules:intent` supplies independent rule bytes: byte 0 below 64 means high priority (otherwise normal); byte 1 below 128 means identity verification is required. Titles replace underscores with spaces, remove question marks and title-case the result. These are synthetic rules, not banking advice. To regenerate deliberately, serialize `generate_policy(4)` and `generate_policy(12)` as indented JSON with a trailing newline and commit both files before a run; changing the rule or artifacts changes the experiment.

## Tools and substitution

`PolicyKB(granularity=4)` loads the frozen policy; alternatively `PolicyKB(entries=entries)` accepts the complete shifted knowledge base, including split or new-intent entries. Each entry must contain `id`, `title`, `department`, `priority`, and `identity_check`, with unique IDs. `get_entry(id)` returns an entry by exact ID. `search_policy(query)` returns at most five entries: exact ID first, then descending count of shared lowercase alphanumeric tokens in query versus entry ID and title, with ID as deterministic tie-breaker. Search returns five even when fewer than five match if the KB has at least five entries. Returned entries are copies.

`augment_ticket(text, ticket_id=...)` appends a stable account ID to the ticket text. It adds a deterministic amount for transaction-related text and a merchant for payment or purchase text; absent distractors are `None`. IDs and values derive from SHA-256 of the ticket ID. Distinct tickets should have distinct IDs. `SupportEnvironment(kb, accounts=None)` implements `search_policy`, `get_account`, `verify_identity`, and `route_ticket`; calls are recorded in `events`, routes in `routes`, and verified account IDs in `verified_accounts`. Account lookups return deterministic synthetic status and balance, overridden by supplied account records. These deterministic tools do not call a model.

`env.substitute(entry_id, account_id, verify, note='', amount=None, merchant=None)` executes a served D1 and explicit D2 without an agent. It searches by the selected entry ID, optionally verifies according to the supplied Boolean (not the entry's gold identity rule), then routes using the entry's department and priority and the derived queue `<department>_queue`. Unknown IDs fail without routing. The returned route retains the supplied copied fields. `env.agent_calls` and `env.agent_cost` are zero; actual model usage and monetary costs must be booked by the caller, including any S1 and tool costs. Shift construction must supply the corresponding changed KB and ticket-to-governing-entry mapping; the base artifacts are not modified.

## Streams and agent baseline

`python -m bench.tasks.streams` regenerates paired control, restructure, CLINC and visible-change streams from the checksum-pinned training datasets. The three 2,400-ticket Banking77 pools are disjoint and change after ticket 1,200; the remaining pool is reserved for development. The restructure marker `[policy cohort revised]` identifies the split cohort in ticket text and in the new entry title; this synthetic cue is a limitation. `shifted_policy(entries, stream, granularity)` supplies the new KB at the shift boundary. The CLINC stream replaces 20% of post-shift tickets with disjoint CLINC training utterances from a frozen banking/credit-card intent list, preserving enough examples for every stream; mappings and new-intent labels are frozen in `clinc_map.json`.

For the visible configuration-change baseline, instantiate `bench.e3a.agent.Agent(..., instructions=instructions_for(row.prompt_version))`; for silent shifts keep the original instructions and change only the KB or traffic. Run `python -m bench.e3a.pilot --mode record` for paid collection or omit `--mode record` for cache-only replay. Pilot tickets come exclusively from the development pool. Agent steps and validated S4 envelopes are written to the pilot trace files; the compiler can consume `TraceStore.of_kind("agent_step")` records.
